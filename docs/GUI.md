# 本机网页控制台

[返回文档索引](README.md)

控制台在默认浏览器打开，从「概览」检查当前部署和进程，在「配置」查看时间、语言和代理设置，在「连接记录」查看活动连接、关闭连接和 DNS。

## 打开控制台

使用 Windows x64 和 64 位 PowerShell 7.5+。控制台二进制 `CdfGui64.exe` 由[网络构建](build.md#构建网络组件和控制台)生成，位于 `out/build/x64-release/bin`。在普通终端中可从工作树打开只读页面。

```powershell
.\scripts\Start-Gui.ps1 -ReadOnly
.\scripts\Start-Gui.ps1 -ReadOnly -Port 0 -NoBrowser
```

新会话默认监听 `127.0.0.1:17862`。指定端口无法监听时，服务自动选择可用的环回端口。`-Port 0` 直接由系统选择端口。同一 Windows 登录会话再次运行时可复用已启动的控制台。实际地址显示在页脚。`-NoBrowser` 输出含一次性票据的本地地址，票据一分钟后失效，使用一次后作废。需要另一个登录票据时重新运行入口。

可写管理依赖 `%ProgramData%\ClaudeDesktopFake\gui` 下有所有权记录的管理发行版。普通终端可复用当前用户已有的发行版，保存或更改时按需请求同一用户的管理员授权。关闭浏览器标签页后服务继续运行。「停止控制台」结束服务并释放端口。

从完整构建安装可写发行版时，在同一账户的 64 位管理员 PowerShell 中执行 `.\scripts\Install-GuiManager.ps1`，再从普通终端运行 `.\scripts\Start-Gui.ps1`。初始环境和已部署 Provider 的升级步骤见[使用与启停](usage.md)。

页脚显示运行中 GUI 可执行文件的 SHA-256 前 12 位。安装版还显示当前服务的发行编号。如果已经选定另一份管理发行版，页脚会同时显示下次启动使用的编号。工作树运行时标为「工作区」。浏览器刷新会重新连接同一个服务，当前连接历史随该服务保留。

## 概览与配置

| 界面 | 查看或操作 |
| --- | --- |
| 概览 | 项目登记、自动刷新、代理配置及每个运行进程的 Provider 状态 |
| 时区与语言 | 分别选 Windows 时区、格式 Locale 和 UI 语言。用「预览」核对 UTC 时钟偏移和 DST |
| 代理与网卡 | 选择物理网卡和命名代理，或从本地 YAML 导入节点。下拉展开时显示名称和 IPv4，收起时显示名称 |
| 打开默认浏览器前询问 | 按当前 Windows 用户设置。开启后，Claude 的外部网页请求需要逐次确认 |
| 检查配置 | 检查部署、路由、规则及冲突。主动点击「测试代理出口」会由测试进程联网查询 ipify |
| 运行进程 | 显示登记、Provider 加载、功能就绪与是否需重新启动。共享 `ssh.exe`、`node.exe` 可显示已核实祖先及「未强制代理」 |

时区和语言在同一个保存动作中提交，各组有独立开关。已运行进程保留启动时快照。当前时钟采用目标时区时，额外 UTC 偏移用 `0`。[时间与区域配置](time-configuration.md)

在按钮旁可以看到后台已接收、等待管理员授权或正在执行等实际阶段及耗时。保存期间仍可编辑。回执确认提交时的内容，随后新增的编辑保留为草稿。如果另一次操作已经更改了同一份配置，页面保留草稿并提示冲突。「放弃草稿并载入已保存值」只重置当前表单。

「项目登记」和「网络代理」显示不同状态。保存或切换后先等后台提交回执，再查看对应进程的实际状态。出错时检查页面显示的冲突、任务进度或需要退出的进程。代理和时间文件的哈希用于检测过期编辑。升级提示指向已有管理发行版的版本检查和恢复流程。[自动刷新](automatic-refresh.md) · [网络状态与边界](Network-Proxy.md)

「禁用 WebRTC」默认开启。测试浏览器的会话以及传输对可识别 STUN／TURN 的处理有独立记录。通用连接上的真实 Claude 会话级效果仍待验证。网络 IPv4 策略作用于受支持的 Hook 路径，详见[网络覆盖表](Network-Proxy.md#覆盖与边界)。

### 打开默认浏览器前询问

在「配置」页开启「打开默认浏览器前询问」。首次使用时默认关闭。开关偏好按当前 Windows 账户保存。已加载本版 Claude 组件的进程在下一次打开外部网页时读取新设置，关闭网页控制台后也能显示 Windows 确认框。

弹窗中央显示 Claude 的应用图标。弹窗按打开时所在显示器的 DPI 和可用区域居中。可用区域较小时，弹窗连同图标、文字和按钮按比例收缩，为任务栏留出空间。弹窗保持在普通窗口上方。圆角地址框可滚动并复制完整 URL，包括路径、查询参数和 `#` 片段。

点击「确认」只批准本次打开。点击「拒绝」、按 Esc 或关闭窗口都会取消打开，并把请求标记为已处理，避免弹出「无法打开链接」。初始焦点在「拒绝」。无法安全显示完整地址、无法创建确认窗或确认后系统打开失败时，调用者仍会收到错误。项目只保存开关，弹窗中的 URL 不进入网页控制台、连接记录或偏好文件。

开关作用于通过项目身份核对、已加载新版 `CdfClaudeTimeZone64.dll` 的进程。它覆盖 `ShellExecuteW`、`ShellExecuteExW` 的普通与延迟导入，以默认或 `open` 动作传入 HTTP/HTTPS 地址时弹出确认。应用内浏览、直接运行浏览器 EXE、其他进程代开以及其他协议不在这个范围内。系统继续使用用户选择的默认浏览器。Electron 的 `shell.openExternal` 在 Windows 通过 Shell 调度外链。[Electron 的 Shell 文档](https://www.electronjs.org/docs/latest/api/shell) · [MSVC 延迟加载说明](https://learn.microsoft.com/en-us/cpp/build/reference/understanding-the-helper-function?view=msvc-170)

升级旧版时，按项目既有流程部署本版 Claude 组件，再重新打开 Claude。如果也启用了网络组件，两份组件需要一同更新，确保像「关于 Anthropic」这样的延迟打开路径会进入确认框。设置页会显示已保存的开关和组件部署状态。可写控制台可以更改开关，只读模式只显示状态。[项目登记](Stage4-Claude.md)

使用 `ctest --test-dir out/build/x64-release -R "^browser_consent$" -V` 可运行原生弹窗回归。它在独立 Windows 桌面显示真实对话框，通过替身库检验普通与延迟调用、窄屏与低可用高度布局、置顶、完整 URL、默认焦点、批准后打开失败、拒绝后取消和开关即时生效。

### 管理代理配置

在「配置 → 代理与网卡」中操作。

1. 点「新建配置」，填写名称、服务器 IPv4、端口和凭据，再点「保存到列表」。名称首尾空白会去除，名称在当前账户内唯一，忽略大小写。例如已有 `Travel` 时不能再新建 `travel`；可以用「重命名」调整同一项的大小写。
2. 从下拉框选代理。展开时可用“名称 · IP”区分节点，收起后下方仍可核对 IP 和端口。旧部署首次显示为「默认代理」，可以直接重命名。
3. 选择已连接的物理网卡，点击「应用所选配置」提交。新建、重命名、导入和浏览列表均保留当前生效的代理。网卡列表只列系统枚举到的物理网卡。原网卡离线时标为「已离线」；已移除时，原 GUID 显示在提示中，须明确选择另一张网卡才能应用或测试。

「导入 YAML」读取单个本地 `.yaml` 或 `.yml` 文件，最大 1 MiB。支持 Mihomo 的 `proxies` 列表、单个节点或节点数组。以下示例使用文档保留地址和示例凭据。

```yaml
proxies:
  - name: 日常代理
    type: vless
    server: 192.0.2.10
    port: 443
    uuid: "11111111-2222-4333-8444-555555555555"
    network: tcp
    tls: true
    flow: xtls-rprx-vision
    servername: edge.example
    client-fingerprint: chrome
    reality-opts:
      public-key: "AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA"
      short-id: "00ab"
```

导入器接受当前传输支持的 VLESS / TCP / REALITY / Vision、IPv4 服务器和 Chrome 指纹。其他协议或传输的节点会跳过并显示数量。可导入节点中出现重名（包括文件内部重名）、必填值无效或 YAML 语法错误时，整次导入取消，原列表保留。成功后选中本次导入的第一项。字段定义见 [Mihomo VLESS 文档](https://wiki.metacubex.one/en/config/proxies/vless/)。

命名配置保存在 `%LOCALAPPDATA%\ClaudeDesktopFake\gui\proxy-profiles.dpapi`，由 Windows DPAPI 按当前用户加密。只读控制台可以查看名称和地址；新建、重命名和导入需要可写控制台。列表接口只返回标识、名称和地址，UUID 等凭据不会随列表返回浏览器。

## 连接记录与 DNS

| 状态或字段 | 解释 |
| --- | --- |
| 建立中／正在转发 | 正在建立代理请求，或已由进程内环回桥转发 |
| 已关闭／暂离 | 连接结束后可显示关闭、握手失败或超时等原因。采集暂时中断且进程仍运行时显示暂离 |
| 目标 | 优先显示域名和端口。HTTPS 可见名称来自 TLS 的 SNI。名称缺失时显示 IP 和端口 |
| DNS | 经记录接口处理的域名、查询类型、IPv4 结果、进程、时间和状态 |

概览分别统计目标进程的登记、网络 Provider 加载、传输就绪及待重启数量。点击 PID 可查看对应连接，筛选框中的 `pid:42` 只匹配 PID 42，也可切换到已关闭或 DNS 查看该 PID 的记录。清空筛选框即可看全部记录。窄窗口默认显示首列和状态，展开行内「详情」可查看其余字段。

「当前连接」的总数包含转发中、建立中和采集暂离。输入域名、IP 或 PID 后，列表显示匹配数与该标签的总数。DNS 与已关闭记录分别保留最近 2,000 条。各自的清除按钮显示整类记录的数量，清除范围包含被筛选隐藏的记录。当前连接不参与清除。

域名和端口是连接级信息。应用加密流量中的 HTTP 路径、参数和自行发起的 DoH 查询正文不属于这张表的记录范围。

记录为空时，依次检查进程是否已加载当前网络组件、连接发生后是否还能访问进程遥测，以及目标值是否被筛选。调用了其他网络组件或由系统服务代发的访问需要独立观测。界面显示「连接记录不可用」时也应核对已部署传输和控制台发行版。[验收范围](validation.md#网络与控制台)

## 验收

可先在隔离浏览器运行交互回归。测试使用本机临时环回端口、独立浏览器配置及模拟数据，覆盖三个开关的圆角、下拉选项、命名与 YAML 导入交互、保存时继续编辑、网卡离线、连接筛选和窄屏详情。需要 Node.js 22+ 和已安装的 Chrome 或 Edge，其他 Chromium 可执行文件可通过 `CDF_TEST_BROWSER` 指定。Go 控制台测试使用临时 DPAPI 文件验证实际 YAML 解析、名称冲突和批量写入。

```powershell
node --test tests/gui_interactions.cjs
go -C transport test ./cmd/cdfgui
```

```powershell
.\scripts\Test-Gui.ps1 -ReadOnly
```

只读模式检查环回端口、登录票据、配置读取和时区预览。可写集成测试另行检查过期配置与管理操作。`-Online` 使用已经配置的代理和隔离探针，有外部 HTTPS 请求。WebRTC 测试单独记录浏览器会话、TURN／TCP、TURN／TLS 与 iframe 的结果。[构建与验证](build.md#验证)
