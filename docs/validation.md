## 证据边界

实际 Store 注册成功不等于真实 Claude 的各 JS 上下文已验收。真实 Claude 主进程、渲染、自然 Worker／Utility 及 LocalSystem 服务内部行为，仍需用户控制启动／重启后读取诊断。隔离 Electron 的结果不能替代这些证据。

公开副本中的构建自动发现、路径整理和文档核验是独立维护工作。后续在自己的机器上应按 [testing.md](testing.md) 重跑并保留新的报告；参考环境数字不是 CI 每次重新执行的宣称。

2026-10-27 修复了“注册值已经全部或部分恢复，但管理记录仍存在”时 Disable 无法完成的问题。门控集成回归扩展到 75 个用例，包含精确原值／类型恢复、第三种值及过滤冲突拒绝、异常回滚和撤销进程中断后的日志恢复，全部通过。Windows PowerShell 5.1 的 Enable、重复 Enable、Disable 和 Status 也取得现场通过结果，并修正了诊断计数使用不兼容类型别名的问题。

本次现场末次检查的 14 个 Claude 包内运行进程均已加载 Provider、通过身份门控，时间状态为 0x1f、区域语言状态为 0x3f，并存在实际 Hook 调用记录。现场配置仍为 schema 2；这些证据只覆盖所读的 Windows Hook 诊断，不表示完成 JavaScript／ICU／WinRT 扩展、网络行为或全部 API 返回值矩阵验收。配置和部署 DLL 保持原内容，应用及服务生命周期由用户控制。

## 发布前检查

2026-10-30 新增自动刷新和开机监控：`Enable` 创建并立即启动 SYSTEM 任务，`Disable` 自动停止观察任务、等待独立刷新进程退出、删除任务并恢复 IFEO。监控测试在 PowerShell 7 和 Windows PowerShell 5.1 下各通过 20 项，覆盖文件事件、生产验签对无签名／其他签名者的排除、隔离进程终止、SYSTEM／管理员共享锁、任务启停、进程退出及原子 JSON 读取。门控回归共 139 项通过，包含受保护目录内新文件在 TLS 前退出、DOS 盘符启动解析、清单损坏和精确恢复；原有 9 项无注册检查通过。

现场已验证实际 SYSTEM 监控订阅进程启动事件，并从空闲状态被受监控目录中的无害文件变动触发：完成重新验签、把无效签名候选列入跳过结果，未把测试文件登记为 Hook 目标。真实启停循环确认关闭后任务不存在、监控与刷新进程均退出、IFEO 恢复且无待恢复事务；时间 JSON 保持原内容。随后重新开启，当前 Store 包为 4.29，22 条文件身份共享 8 个映像名。验证包含开机触发器和实际 SYSTEM 运行，没有主动重启设备，也没有用这些结果替代真实 Claude／服务的运行时返回值验收。全新文件名仍存在启动后检测窗口，详见 [automatic-refresh.md](automatic-refresh.md)。
